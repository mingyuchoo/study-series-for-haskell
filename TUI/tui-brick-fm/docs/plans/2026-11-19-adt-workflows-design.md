# ADT 작업 상태 머신

## 목적과 범위

기존 키 바인딩, 화면, 파일 정책을 보존하면서 모든 제품 사용 사례의 진행 순서를 명시적인 상태 머신으로 표현한다. 시작, 탐색, 검색, 입력, 테마, 언어, 편집기 설정, 복사, 이동, 이름 변경, 생성, 삭제, 미리보기, 편집기 실행, 셸 실행, 패널 갱신, 종료가 대상이다. OS 재귀 파일 작업과 개발/배포 스크립트는 기존 어댑터 책임으로 유지한다.

## 분석과 선택

기존 Mode는 화면 상태를 표현하지만 Program의 Await는 후속 함수를 저장하고 StateT/ExceptT가 작업 단계를 숨긴다. 설정 저장은 실행기가 전후 상태를 비교해 결정한다.

화면 Mode만 확장하면 효과 실행 단계가 그대로 숨겨진다. 문자열 이벤트를 받는 단일 상태 머신은 요청과 응답의 잘못된 조합을 허용한다. 따라서 GADT 요청과 응답 타입에 맞춘 Phase ADT를 사용한다. 이 선택은 기존 Haskell 및 패키지 구조에 맞으며 추가 의존성이 필요 없다.

## 설계

- Program은 완료 값 Done 또는 타입이 일치하는 Request와 Phase를 담는 Await다. 함수나 임의의 효과를 저장하지 않는다.
- Phase는 시작 단계, 실행 중 작업 단계, 단일 요청 결과 반환으로 구성한다. StartupStep과 TaskStep이 각 진행 단계에 필요한 값만 보존한다.
- Machine.resume은 Phase와 Either FileError response를 받아 다음 Program을 반환하는 순수 함수다. IO 없이 한 단계씩 검증할 수 있다.
- UI 입력은 순수 함수로 처리한다. KeySequence와 Lifecycle ADT로 접두 명령과 실행/종료 상태를 표현한다. 기존 Mode와 독립적인 테마 미리보기는 유지한다.
- 설정 저장도 SaveSettings 요청이다. 성공 시 후보 상태를 확정하고 실패 시 이전 설정 및 입력 상태를 복구한다. 실행기는 정책을 판단하지 않는다.
- 두 패널 갱신은 두 읽기가 모두 성공해야 반영한다. 이미 성공한 파일 변경은 후속 갱신 실패로 되돌리지 않는다. 오류는 기존 입력과 함께 Status로 전달한다.
- Runtime은 요청을 주입된 파일, 프로세스, 설정 저장 포트로 전달하고 응답을 resume에 전달한다.

## 경계 및 검증

domain은 application이나 외부 어댑터를 참조하지 않는다. 순수 application은 Effects를 import하지 않는다. 내부 구현 모듈은 공개하지 않고 패키지 간에는 패키지 모듈 이름으로만 import한다. 소스 주석을 추가하지 않는다.

기존 전체 테스트에 순수 단계 전이, 시작 단계별 실패, 대상 검사/변경 실패, 패널 읽기 실패, 설정 저장 성공/복원, 키 접두/종료 테스트를 추가한다. 전체 빌드는 -Werror 및 불완전 패턴 경고를 사용하고 아키텍처 검사와 PTY 키 바인딩 테스트를 실행한다.

# ADT 작업 흐름 설계

현재 검색 상태는 Brick List와 Vty 속성에 의존하고, Event는 순수 상태 변경과 파일 읽기를 함께 수행한다. Main의 입력 감지, 입력 수집, 설정 읽기, TUI 실행, 출력 역시 암묵적인 순서에 의존한다.

목표는 기존 검색, 키바인딩, 레이아웃, 파이프 입력과 종료 시 현재 선택 출력 동작을 보존하면서 모든 애플리케이션 작업 흐름을 명시적인 ADT 전이로 표현하는 것이다. ESC와 Enter의 종료 사유는 구분하되 기존처럼 두 경우 모두 현재 선택을 출력한다.

## 접근 방식

기존 레코드에 상태 태그만 추가하면 Brick 의존성과 숨은 I/O 순서가 남는다. 전체 동작을 하나의 거대한 상태 타입에 넣으면 디렉토리 탐색과 검색 화면이 결합된다. 따라서 독립적인 시작, 탐색, 세션 상태 머신과 명령 인터프리터를 사용한다. 이 선택은 요청의 Clean Architecture와 순수성 규칙에 따른 구현 판단이다.

## 패키지 경계

- `packages/domain`: base만 의존한다. 검색/선택, 키바인딩 설정 값, 세션/미리보기 상태와 순수 전이, 디렉토리 탐색 계획을 제공한다. 외부 라이브러리 타입을 사용하지 않는다.
- `packages/application`: 도메인에만 의존한다. 입력 감지부터 출력 완료까지 Workflow ADT와 전이, 효과 포트 및 실행기를 제공한다.
- `packages/terminal`: Brick/Vty, YAML, 파일 시스템, stdin/stdout 구현과 기존 UI를 제공한다. 세션 명령을 실행한 결과를 다시 이벤트로 전달한다.
- `apps/fzh`: 구체적인 포트를 조립하는 진입점이다. 루트 fzh 패키지는 실행 파일 빌드를 유지한다.

## 상태 머신

시작은 대기 → 입력 소스 감지 → 입력 수집 → 설정 로드 → 세션 실행 → 결과 출력 → 완료로 이동한다. 빈 입력은 기존 메시지 출력으로 이동하고, 실패는 명시적인 실패 상태로 이동한다. 잘못된 단계의 이벤트와 완료 후 이벤트는 효과를 생성하지 않는다. 설정 파일 없음/해석 실패는 구별된 결과로 반환하며 해석 실패 경고를 stderr에 표시한 뒤 기본 설정을 적용한다.

세션은 Browsing/Finished, 미리보기는 NoPreview/Loading/Loaded/Failed로 표현한다. 순수 전이는 입력 편집, 검색, 이동, 크기 변경, 선택/취소와 미리보기 완료를 처리한다. 읽기 명령에는 증가하는 요청 식별자와 경로를 포함하며 현재 요청과 다른 응답은 무시한다. 같은 선택에는 중복 읽기를 하지 않고, 빈 결과에서는 미리보기를 지운다. 종료 상태는 이후 이벤트를 받지 않는다.

디렉토리 탐색은 경로 검사/디렉토리 열기/완료 상태와 명령으로 진행한다. 숨김 및 빌드 경로 제외 정책은 순수 도메인에 위치한다. 읽기 실패는 탐색 문제 목록에 보관하고 나머지 경로를 계속 처리한다. 인터프리터는 IOException만 변환하여 비동기 취소를 삼키지 않는다.

## 검증

기존 44개 회귀 테스트를 유지한다. 새 테스트는 순수 상태 전이, 선택 경계, 점수 및 경로 깊이 정렬, 빈 입력/검색 결과, 설정 실패, 미리보기 실패/오래된 응답/중복 요청, 종료 후 이벤트, 탐색 실패와 효과 포트 실행을 검사한다. Stack workspace 전체 빌드와 테스트, 소스의 주석 및 의존성 경계 검사를 수행한다. Docker와 CI 및 실행/배포 스크립트의 소스 경로도 새 구조에 맞춘다.

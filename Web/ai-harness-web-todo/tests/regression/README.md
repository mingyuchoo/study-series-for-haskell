# Regression Tests

과거 결함과 사고가 재발하지 않도록 최소 재현을 실행 가능한 검증으로 보존합니다.

실행 위치: `../../src/store/tests`

## 현재 보존 중인 재현

| 사고 | 재현 내용 |
|---|---|
| [INC-2026-001](../../docs/incidents/INC-2026-001.md) | 세 표면이 같은 데이터베이스에 동시에 쓰는 상황. WAL 저널 모드와 busy timeout이 적용되어 있는지 확인합니다 |
| [INC-2026-001](../../docs/incidents/INC-2026-001.md) | 한 연결이 계속 읽는 동안 다른 두 연결이 쓰는 상황. 브라우저 탭을 열어 둔 사용 방식입니다 |

| [INC-2026-001](../../docs/incidents/INC-2026-001.md) | 잠금 경합으로 실패한 초기화의 재시도. `busy_timeout`이 덮지 못하는 경우가 있습니다 |

사고 당시 표면은 둘이었습니다. `web`이 더해지면서 셋으로 늘렸습니다. 이 표는 표면 수를 따라가야 하며, 따라가지 않으면 `LESSON-002`를 다시 어기게 됩니다.

## 자동화되지 않은 재현

프로세스 간 잠금 경합은 여기서 자동으로 재현하지 않습니다. 같은 프로세스의 연결은 SQLite 내부에서 직렬화되어 경합이 가려지기 때문입니다(`LESSON-005`). 절차는 `../../src/store/docs/architecture.md`의 "수동 확인 절차"에 있습니다.

## 원칙

- 사고 문서에 조치를 적는 것으로 끝내지 않습니다. 조치가 사라지면 실패하는 테스트를 함께 남깁니다.
- 재현은 사고 당시의 조건을 테스트가 감당할 크기로 줄이되, 실패를 만들어낸 구조는 유지합니다.
- 제품이 약속한 사용 방식은 테스트도 그 방식으로 실행해야 지켜집니다 (`../../docs/incidents/lessons.md`의 `LESSON-002`).

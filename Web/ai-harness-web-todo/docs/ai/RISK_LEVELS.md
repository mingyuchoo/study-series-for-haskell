# Change Risk Levels

## Level 0: 문서 또는 비동작 변경

예: 오탈자, 깨진 링크, 주석 보강, 의미를 바꾸지 않는 정리

- `scripts/context/validate-context.sh`로 검증합니다.
- Canonical Source의 의미가 바뀌지 않았는지 확인합니다.

## Level 1: 국소적이며 되돌리기 쉬운 변경

예: 내부 리팩터링, 오류 메시지 문구, 새 CLI 옵션 추가, 테스트 보강

- 해당 패키지의 테스트와 `scripts/quality/lint.sh`를 실행합니다.
- 패키지 경계와 공개 계약이 유지되는지 확인합니다.

## Level 2: 여러 패키지 또는 공개 동작 변경

예: 새 API 필드, 새 상태 전이, 조회 조건 추가, 하위 호환 스키마 확장, CLI 출력 형식 변경

- 서면 영향 분석과 활성 계획이 필요합니다.
- 계약 문서를 코드와 같은 변경에서 갱신합니다.
- 계약 테스트와 생성 문서를 함께 갱신합니다.
- 기존 데이터베이스 파일로 새 실행 파일을 여는 경로를 확인합니다.

## Level 3: 고위험 또는 되돌리기 어려운 변경

예: 파괴적 SQLite 마이그레이션, 열 제거나 타입 변경, 삭제 동작의 의미 변경, 인증 도입, 데이터를 외부로 보내는 의존성 추가, `core`의 순수성 완화

- 명시적인 사람의 승인과 ADR이 필요합니다.
- 백업과 복구 절차, 중단 조건을 미리 정합니다.
- 보안 및 회귀 검증을 포함합니다.
- 되돌릴 수 없는 데이터 변경은 사용자가 먼저 백업할 수 있는 경로를 제공합니다.

## 판단 기준

위험 수준은 변경 파일 수가 아니라 실패 시 영향, 가역성, 불확실성과 경계 변경 여부로 정합니다.

이 제품에서 가장 되돌리기 어려운 것은 **사용자의 데이터**입니다. 코드는 되돌릴 수 있지만 사용자의 할 일 기록은 되돌릴 수 없습니다. 데이터를 잃을 수 있는 변경은 규모와 무관하게 Level 3입니다.

# Context Ownership

사람은 목적, 의미와 Why를 관리하고 기계는 현재의 검증 가능한 Fact를 관리합니다. AI는 두 영역을 연결하고 갱신을 제안하거나 수행할 수 있지만 권위는 문서 유형과 승인 절차에서 나옵니다.

| 영역 | 저장 내용 | 주 관리 주체 | 검증 방식 |
|---|---|---|---|
| `docs/product` | 목적, 가치, 제품 불변조건 | 사람 | 제품 검토와 수용 기준 |
| `docs/domain` | 비즈니스 의미와 규칙 | 사람과 AI | 도메인 검토와 `core` 테스트 |
| `docs/decisions` | 선택의 이유와 트레이드오프 | 사람과 AI | 승인 상태와 구현 검사 |
| `docs/contracts` | 표면과 저장 형식의 공개 약속 | 사람과 기계 | 계약 테스트 |
| `docs/incidents` | 실패 사실과 반복 가능한 교훈 | 사람과 AI | 증거, 조치와 회귀 테스트 |
| `docs/generated` | 현재 시스템에서 추출한 사실 | 기계 | 생성기 재실행과 차이 검사 |
| `src/*/src` | 실행 가능한 규칙과 구현 | 사람과 AI | 타입 검사와 테스트 |
| `src/*/tests` | 실행 가능한 규칙 | 기계 검증 | CI 실행 |
| `scripts` | 검증 체계 자체 | 사람 | CI 실행 |
| `AGENTS.md` | Codex 탐색 지도 | 사람과 AI | 크기와 링크 검사 |
| `CLAUDE.md` | Claude 탐색 지도 | 사람과 AI | 크기와 링크 검사 |
| `docs/ai` | AI 작업 프로토콜 | 사람 중심 | 정책 검토와 CI |

## 변경 책임

- 의미와 정책을 바꾸는 변경은 해당 사람 소유자의 검토가 필요합니다.
- 생성 문서는 직접 편집하지 않고 생성 원본이나 생성기를 수정합니다. 원본 목록은 `INDEX.md`의 8절에 있습니다.
- AI가 발견한 정보는 권위 있는 원본과 검증을 거친 뒤에만 Canonical Context가 됩니다.
- 소유자가 없거나 권위가 충돌하는 고위험 변경은 추측으로 진행하지 않습니다.

## 사용자 데이터의 소유자

`todo.db`와 그 안의 할 일은 전적으로 사용자의 것입니다. 이 저장소의 어떤 문서나 코드도 사용자 데이터의 사본을 담지 않습니다. 테스트는 항상 임시 디렉터리에 새 데이터베이스를 만들고 실행 후 버립니다.

# Task List Domain

## 책임

할 일을 담는 목록의 의미를 정의합니다. 목록은 사용자가 맥락을 나누는 가장 큰 단위입니다.

## 핵심 개념

- List: 할 일의 묶음. 사용자에게는 "목록"으로 부릅니다.
- List ID: 목록을 가리키는 이름. 태그와 같은 문자 규칙을 사용하며 소문자로 정규화합니다.
- Inbox: 목록을 지정하지 않은 할 일이 들어가는 기본 목록. 이름은 `inbox`입니다.

## 불변조건

- 모든 할 일은 정확히 하나의 목록에 속합니다. 목록이 없는 할 일은 존재하지 않습니다.
- 목록을 지정하지 않으면 `inbox`에 들어갑니다. 사용자에게 목록을 먼저 만들라고 요구하지 않기 위한 결정입니다.
- 목록은 별도의 개체로 미리 만들지 않습니다. 할 일에 이름을 붙이면 그 목록이 존재하는 것으로 간주합니다.
- 목록 이름은 태그와 같은 정규화 규칙을 따릅니다. 두 어휘가 다르면 사용자가 규칙을 두 벌 외워야 합니다.
- 목록에 속한 할 일이 모두 사라져도 오류가 아닙니다. 빈 목록은 그냥 보이지 않을 뿐입니다.

## 목록과 태그의 차이

| | 목록 | 태그 |
|---|---|---|
| 개수 | 할 일마다 정확히 하나 | 할 일마다 0개 이상 |
| 목적 | 맥락 분리 | 교차 분류 |
| 기본값 | `inbox` | 없음 |

하나의 할 일을 두 맥락에 동시에 두고 싶다면 목록이 아니라 태그를 사용합니다.

## 경계

목록은 접근 제어 단위가 아닙니다. 현재 제품에는 사용자 개념과 권한 개념이 없습니다. 목록을 공유 단위로 쓰려는 변경은 인증 경계 도입을 뜻하며 Level 3입니다.

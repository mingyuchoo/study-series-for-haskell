# Task Domain

## 책임

할 일 하나의 의미와 수명 주기를 정의합니다. 이 도메인이 제품의 중심이며 나머지 도메인은 할 일을 분류하거나 배치하는 역할입니다.

## 핵심 개념

- Task: 사용자가 언젠가 끝내려는 하나의 작업. 제품 문서와 코드에서 일관되게 "할 일"로 부릅니다.
- Task ID: 저장소가 부여하는 변경되지 않는 내부 식별자. 재사용하지 않습니다.
- Title: 사용자가 알아볼 수 있는 한 줄 설명. 공백만으로는 만들 수 없습니다.
- Status: 할 일이 수명 주기의 어디에 있는지를 나타내는 값.

## 상태 기계

```text
        +---------------------+
        v                     |
    pending  <----------  in_progress
        |   \                 |
        |    \                |
        v     v               v
      done  archived  <----  archived
        |
        +--> pending  (다시 열기)
        |
        +--> archived
```

허용된 전이는 다음과 같습니다.

| 현재 상태 | 이동할 수 있는 상태 |
|---|---|
| `pending` | `in_progress`, `done`, `archived` |
| `in_progress` | `pending`, `done`, `archived` |
| `done` | `pending`, `archived` |
| `archived` | 없음 |

## 불변조건

- 새 할 일은 항상 `pending`으로 시작합니다. 만들면서 완료 상태로 둘 수 없습니다.
- 정의된 상태 기계 밖의 전이를 거부합니다.
- `archived`는 종료 상태입니다. 보관을 되돌리는 요구가 생기면 전이를 임의로 추가하지 않고 ADR로 결정합니다.
- 같은 상태로 바꾸라는 요청은 오류가 아니라 무변경입니다. 같은 요청을 여러 번 보내도 한 번의 효과만 남습니다.
- 완료한 할 일은 다시 열 수 있습니다. 완료를 되돌릴 수 없게 만들면 사용자가 실수를 교정할 방법이 사라집니다.
- 삭제는 상태가 아니라 별개의 되돌릴 수 없는 동작입니다. 보관과 혼동하지 않습니다.
- `updated_at`은 실제 변경이 있을 때만 갱신합니다. 무변경 요청이 시각만 바꾸면 멱등성이 관측 가능하게 깨집니다.

## 경계

Task 도메인은 저장 방식과 표시 형식을 알지 못합니다. 시각도 스스로 읽지 않고 경계에서 주입받습니다. 근거는 `../decisions/ADR-0002-effect-boundary.md`에 있습니다.

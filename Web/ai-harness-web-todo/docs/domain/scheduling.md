# Scheduling Domain

## 책임

마감일과 우선순위, 그리고 그것들이 목록 순서에 미치는 영향을 정의합니다.

## 핵심 개념

- Due Date: 할 일을 끝내야 하는 날짜. 시각이 아니라 날짜입니다.
- Priority: 사용자가 지정하는 상대적 중요도. `low`, `normal`, `high`, `urgent` 네 단계입니다.
- Sort Order: 목록을 보여주는 순서. 마감일, 우선순위, 생성 시각 중 하나를 고릅니다.

## 불변조건

- 마감일은 날짜이며 시각을 갖지 않습니다. "언제까지"는 사용자의 하루 단위 감각이고, 시각을 붙이면 시간대 문제가 생깁니다.
- 새 할 일에 과거 마감일을 지정할 수 없습니다. 이미 늦은 일을 만들려는 것은 대개 오타입니다.
- 이미 만들어진 할 일의 마감일이 지나가는 것은 정상입니다. 시스템이 자동으로 상태를 바꾸거나 삭제하지 않습니다.
- 마감일은 없을 수 있습니다. 없는 것과 지우는 것은 구분되지만, 결과 상태는 같습니다.
- 우선순위의 기본값은 `normal`입니다.
- 우선순위는 상태에 영향을 주지 않습니다. `urgent`인 할 일도 다른 할 일과 같은 상태 기계를 따릅니다.

## 정렬 규칙

| 기준 | 순서 |
|---|---|
| 마감일 | 이른 날짜부터. 마감일이 없는 할 일은 항상 뒤 |
| 우선순위 | `urgent`부터 `low`까지. 같으면 마감일 순 |
| 생성 시각 | 먼저 만든 것부터 |

같은 순위의 항목은 식별자 순으로 안정화합니다. 같은 목록을 두 번 조회했을 때 순서가 달라지지 않게 하기 위함입니다.

## 시간대

- 저장하는 시각은 모두 UTC입니다.
- 마감일은 시간대가 없는 날짜입니다. "오늘"을 판단할 때만 실행 환경의 시각을 UTC 날짜로 변환해 사용합니다.
- 도메인은 시계를 읽지 않습니다. 오늘 날짜도 경계에서 주입받습니다.

이 단순화는 단일 시간대 사용자를 전제합니다. 여행이나 협업으로 전제가 깨지면 그때 시간대를 도입하고, 그것은 계약 변경입니다.

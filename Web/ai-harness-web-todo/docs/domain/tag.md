# Tag Domain

## 책임

할 일을 목록과 교차하여 분류하는 태그의 의미와 검색 규칙을 정의합니다.

## 핵심 개념

- Tag: 할 일에 붙이는 짧은 분류 이름.
- 정규화: 앞뒤 공백을 제거하고 소문자로 바꾸는 과정. 저장 전에 항상 수행합니다.

## 불변조건

- 태그는 소문자로 정규화됩니다. `Work`와 `work`와 ` WORK `는 같은 태그입니다.
- 정규화 후 중복은 하나로 합쳐집니다. 같은 태그가 한 할 일에 두 번 붙지 않습니다.
- 허용 문자는 문자, 숫자, `-`, `_`뿐입니다. 공백과 구분자는 허용하지 않습니다.
- 태그 하나는 32자 이하, 할 일 하나는 16개 이하의 태그를 가집니다.
- 태그 목록 중 하나라도 규칙을 어기면 요청 전체를 거부합니다. 일부만 적용해 사용자가 무엇이 저장되었는지 모르게 만들지 않습니다.
- 태그는 독립된 개체가 아닙니다. 마지막 할 일에서 떨어지면 그냥 사라집니다.

## 검색 의미

- 여러 태그를 지정하면 논리곱입니다. 지정한 태그를 모두 가진 할 일만 나옵니다.
- 논리합 검색은 제공하지 않습니다. 필요해지면 질의 문법을 도입하는 것이 아니라 계약을 먼저 확장합니다.
- 태그 조건과 상태 조건과 목록 조건은 서로 논리곱으로 결합합니다.

## 문자 규칙의 이유

허용 문자를 좁게 잡은 이유는 태그가 명령줄 인자, URL 질의 문자열, HTML 본문에 그대로 나타나기 때문입니다. 인용과 이스케이프가 필요한 문자를 허용하면 표면마다 다르게 해석될 위험이 생깁니다.

## 경계

조회 조건의 평가는 `Todo.Core.Filter` 한 곳에서만 이루어집니다. 저장 계층이 조건을 자체 구현하면 CLI와 HTTP API가 서로 다른 결과를 보여줄 수 있습니다.

- 논리곱 검색: `src/core/tests/Todo/Core/FilterSpec.hs`

# Product Invariants

구현과 관계없이 지켜야 하는 규칙입니다. 각 항목은 실행 가능한 검증과 연결되어 있습니다.

| ID | 불변조건 | 검증 방식 | 소유자 |
|---|---|---|---|
| PROD-INV-001 | 사용자가 명시적으로 요청하지 않은 할 일 삭제나 상태 변경을 만들지 않습니다. | 계약 및 통합 테스트 | Product, core |
| PROD-INV-002 | 저장에 성공했다고 알린 할 일은 비정상 종료 후에도 유실되지 않습니다. | 통합 및 회귀 테스트 | Product, store |
| PROD-INV-003 | 모든 표면이 보고하는 상태는 저장소의 확정 상태와 일치합니다. | 계약 및 회귀 테스트 | Product, cli, api, web |
| PROD-INV-004 | 같은 요청을 여러 번 보내도 한 번의 효과만 남습니다. | 단위, 통합, 계약 테스트 | Product, core |
| PROD-INV-005 | 사용자 데이터는 사용자가 지정한 로컬 파일 밖으로 나가지 않습니다. | 아키텍처 검사 | Product |

## 구조적 근거

`PROD-INV-003`은 문서상의 약속이 아니라 구조로 지탱합니다. `cli`, `api`, `web`은 규칙을 각자 구현하지 않고 `Todo.Core.UseCase`를 함께 호출합니다. 조회 조건도 `Todo.Core.Filter` 한 곳에서만 평가합니다. 어느 표면에든 규칙을 복제하는 변경은 이 불변조건을 구조적으로 무너뜨립니다.

표면의 개수 자체는 위험이 아닙니다. 복제가 위험입니다. 새 표면이 호출만 한다면 창이 몇 개든 같은 답이 나옵니다.

`PROD-INV-005`는 이 제품에 네트워크 클라이언트가 없다는 사실에 의존합니다. 외부로 요청을 보내는 의존성을 추가하는 변경은 Level 3입니다.

# Terminology

| 용어 | 정의 | 사용하지 않을 표현 |
|---|---|---|
| 할 일 | 사용자가 언젠가 끝내려는 하나의 작업 | 태스크, 아이템, 이슈 |
| 목록 | 할 일이 정확히 하나 속하는 묶음 | 프로젝트, 폴더, 카테고리 |
| 태그 | 할 일을 목록과 교차하여 분류하는 이름 | 라벨, 키워드 |
| 상태 | 할 일이 수명 주기의 어디에 있는지 | 진행률, 완료 여부 |
| 보관 | 목록에서 치우되 삭제하지는 않는 종료 상태 | 삭제, 숨김 |
| 삭제 | 되돌릴 수 없이 데이터를 없애는 동작 | 보관, 완료 |
| 마감일 | 할 일을 끝내야 하는 날짜 | 마감 시각, 일정 |
| 우선순위 | 사용자가 지정하는 상대적 중요도 | 긴급도, 중요도 점수 |
| 계약 | 외부에 공개되어 호환성을 관리하는 약속 | 내부 구현, 인터페이스 |

## 어휘가 코드에 나타나는 방식

상태와 우선순위의 값 이름은 도메인, 저장소, CLI, HTTP API, 브라우저 표면에서 모두 같은 문자열입니다.

| 개념 | 값 |
|---|---|
| 상태 | `pending`, `in_progress`, `done`, `archived` |
| 우선순위 | `low`, `normal`, `high`, `urgent` |

이 이름들의 Canonical Source는 `src/core`의 `Todo.Core.Types`입니다. 표면마다 다른 이름을 노출하면 사용자가 같은 개념을 두 번 배워야 합니다.

브라우저 표면에서는 값 이름을 사람이 읽는 문구로 바꾸고 싶은 압력이 생깁니다. `in_progress`를 "진행 중"으로 보여주는 것은 표시의 문제이므로 허용하지만, 그 문구가 저장되거나 질의 문자열에 실리지는 않습니다. 화면에 보이는 말과 계약에 실리는 값은 다른 층입니다.

## 보관과 삭제

이 둘을 구분하는 것이 제품의 핵심 어휘 결정입니다. 보관은 상태 전이이고 되돌릴 수 없지만 데이터는 남습니다. 삭제는 상태가 아니며 데이터가 사라집니다. 사용자 문구에서 "지우기"라는 말을 두 동작에 함께 쓰지 않습니다.

# api Architecture

## Boundaries

- 전송 표현(`Todo.Api.Types`)과 도메인 타입을 분리합니다. 도메인 구조 변경이 곧바로 계약 파손이 되지 않게 하기 위함입니다.
- 라우트는 `Todo.Api.Routes`의 타입이 소유합니다. 핸들러 목록이 타입과 어긋나면 컴파일되지 않습니다.
- 핸들러는 유스케이스를 호출하고 오류를 HTTP로 옮기기만 합니다. 규칙을 다시 구현하지 않습니다.
- 시각은 핸들러에서 읽어 유스케이스에 주입합니다. 도메인은 시계를 모릅니다.
- 수신 주소는 루프백으로 고정합니다. 인증이 없는 표면에서 접근 경로 제한은 설정이 아니라 경계입니다.

## Error Mapping

| 원인 | 상태 | `code` |
|---|---|---|
| 값 검증 실패, 인식할 수 없는 열거값 | 400 | `invalid_request` |
| 경로 매개변수 형식 오류 | 400 | Servant 기본 응답 |
| 존재하지 않는 식별자 | 404 | `not_found` |
| 허용되지 않은 상태 전이 | 409 | `invalid_transition` |

소비자는 HTTP 상태가 아니라 `code`로 분기합니다. 상태 코드는 전송 계층의 신호이고 `code`가 안정적인 약속입니다.

## Testing

계약 테스트는 실제 포트를 열지 않고 `Network.Wai.Test`로 애플리케이션에 직접 요청합니다. 포트 충돌과 대기 없이 결정적으로 실행하기 위한 선택입니다.

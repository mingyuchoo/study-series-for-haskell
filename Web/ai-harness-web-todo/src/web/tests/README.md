# web Tests

HTML 출력과 설정 해석을 검증합니다. 검증 대상 목록은 `../docs/invariants.md`에 있습니다.

```bash
cabal test web
```

## 규칙

- 렌더링은 순수 함수 `Todo.Web.View`를 직접 호출해 검증합니다. 실제 포트를 열지 않습니다.
- 이스케이프 검증은 선택이 아니라 필수입니다. 사용자 입력이 그대로 출력에 나타나면 실패해야 합니다.
- 외부 출처 참조가 출력에 섞이지 않는지 검사합니다. `PROD-INV-005`를 화면 층에서 지키는 방법입니다.
- 상태 표시 문구를 바꿀 때는 계약에 실리는 값(`statusName`)이 함께 바뀌지 않았는지 확인합니다. 두 값은 다른 층입니다.

## 표면 일관성

세 표면이 같은 목록을 보이는지는 한 테스트 스위트에서 확인할 수 없습니다. 어댑터가 서로를 import할 수 없기 때문입니다(`../../../ARCHITECTURE.md`의 의존 규칙 5).

대신 구조적 근거를 나누어 고정합니다.

| 근거 | 검증 위치 |
|---|---|
| 기본 상태 조건을 한 함수가 정한다 | `../../core/tests/Todo/Core/FilterSpec.hs` |
| 웹은 조건을 만들기만 하고 평가하지 않는다 | `./Todo/Web/RouteSpec.hs` |
| 뷰가 받은 목록을 다시 거르거나 정렬하지 않는다 | `./Todo/Web/ViewSpec.hs` |
| 세 연결이 같은 확정 상태를 본다 | `../../store/tests/Todo/Store/RegressionSpec.hs` |

세 프로세스를 함께 띄워 비교하는 것은 수동 확인으로 남습니다. 절차는 `../docs/invariants.md`에 있습니다.

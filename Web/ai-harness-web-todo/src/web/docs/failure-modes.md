# web Failure Modes

| 실패 방식 | 탐지 | 안전한 동작 | 복구 |
|---|---|---|---|
| `TODO_WEB_PORT`가 숫자가 아님 | `Todo.Web.Config`의 해석 | 기본 포트로 기동하고 실제 포트를 로그에 출력 | 로그의 포트로 접속하거나 값을 고쳐 재기동 |
| 포트가 이미 사용 중 | 기동 시 bind 실패 | 기동하지 않음. 조용히 다른 포트로 옮기지 않음 | `TODO_WEB_PORT`로 다른 포트 지정 |
| 데이터베이스 파일을 열 수 없음 | `Todo.Store.Sqlite`의 `openStore` | 기동하지 않음. 빈 목록으로 위장하지 않음 | 경로와 권한 확인 |
| 저장 계층 잠금 경합 | 저장 계층의 busy timeout | 대기 후 진행 | `../../../docs/incidents/INC-2026-001.md` 참고 |
| 손상된 저장 데이터 | `Todo.Store.Sqlite`의 `StoreError` | 기본값으로 위장하지 않고 오류 화면 | 데이터 조사 |
| 검증에 실패한 폼 입력 | `Todo.Core.Validation` | 400. 저장소 미변경 | 사용자가 입력 수정 |
| 허용되지 않은 상태 전이 | `Todo.Core.Status` | 409. 저장소 미변경 | 현재 상태 확인 |
| 없는 할 일을 수정하거나 삭제 | `UseCaseError` | 404 | 목록 재조회 |
| 다른 사이트에서 온 변경 요청 | `Todo.Web.Security` | 403. 저장소 미변경 | 정상 경로는 화면의 폼입니다 |
| `Sec-Fetch-Site`를 보내지 않는 브라우저 | 같은 검사 | 403. 변경이 동작하지 않음 | 조회는 됩니다. 변경은 `cli`를 사용 |
| 지나치게 큰 폼 본문 | 요청 길이 확인 | 413. 본문을 읽지 않음 | 입력을 줄임 |

## 수신 주소

이 표면은 인증이 없습니다. 실행 파일은 `127.0.0.1`에만 바인딩하며 수신 주소를 바꾸는 설정이 없습니다.

| 증상 | 원인 | 대응 |
|---|---|---|
| 다른 기기에서 연결이 거부됨 | 의도된 동작입니다 | 같은 기계에서 접속합니다. 원격 접속은 `../../../docs/product/vision.md`의 비목표입니다 |

## 브라우저를 켜 둔 상태

브라우저 탭을 열어 두면 데이터베이스 연결이 상시 유지됩니다. 이는 CLI 중심 사용에서는 없던 패턴입니다.

| 증상 | 원인 | 대응 |
|---|---|---|
| 탭 두 개에서 같은 할 일을 수정하면 나중 쓰기가 이김 | 낙관적 동시성 제어가 없습니다 | 알려진 결함입니다. `../../../docs/tech-debt/active.md`의 `TD-003`으로 추적합니다 |
| 뒤로 가기 후 폼을 다시 제출해도 중복 생성되지 않음 | 변경 후 303으로 되돌려 보냅니다 | 정상 동작입니다 |
| 서버 재기동 후 열려 있던 탭이 오래된 내용을 보임 | 서버 렌더링 결과의 자연스러운 특성 | 새로 고침 |

# UX

## 화면 목적

관리자가 Task의 우선순위와 진행 상태를 한 화면에서 이해하고, 세부 업무·결과물 검토·Outcome 조립까지 이어서 처리할 수 있게 한다.

## 주요 인터랙션

| 영역 | 동작 |
| --- | --- |
| 생성 폼 | 보드 상단의 `새 업무 등록`에서 우측 서랍을 열고, 긴급도, 중요도, 제목, 기대 결과물, 설명, Task Owner, Outcome Owner 순서로 입력한다. |
| 실행 분류 | 즉시 실행, 계획 수립, 위임, 제거별로 해당 Task의 요약 카드를 표시한다. 카드를 누르면 상세 패널을 연다. |
| 상태 스윔레인 | `Draft`, `Reviewed`, `Submitted`, `Approved`, `Effective` 컬럼에서 Task를 확인하고 드래그로 상태를 변경한다. |
| Task 카드 | 제목, Task Owner, 실행 분류 또는 진행 상태, 결과물 진행 상태와 설명 요약을 표시한다. |
| 상세 패널 | 실행 분류와 진행 상태를 별도 항목으로 표시하고, 전체 설명, 수정·삭제, 결과물 제출, 승인·수정 요청을 제공한다. 수정은 생성과 동일한 우측 서랍을 사용한다. |
| 알림 | 성공·실패 메시지를 토스트로 표시하고 약 3초 후 자동으로 숨긴다. |

## 표현 원칙

- 상태 값은 한국어로 표시하되 API의 영문 열거형과 명확히 매핑한다.
- 카드에는 요약만 두고 상세 정보는 패널에서 보여 정보 밀도를 조절한다.
- 실행 분류는 업무를 찾기 위한 우선순위 축이고, 상태 스윔레인은 도메인 진행 상태 축이다. 두 축의 값과 변경 행동을 시각적으로 분리한다.
- 넓은 화면에서는 사이드바를 활용하고, 상태 스윔레인은 가용 폭에 맞게 여러 행으로 자동 재배치한다. 좁은 화면(약 700px 이하)에서는 전체 콘텐츠와 상태 컬럼을 한 열로 표시한다.
- 색상만으로 상태를 구분하지 않고 텍스트 레이블을 함께 제공한다.

## 접근성과 후속 개선

- 드래그 앤 드롭과 동일한 상태 변경을 키보드·버튼으로도 제공해야 한다.
- 폼 필드에 연결된 오류 메시지와 명확한 포커스 상태를 유지해야 한다.
- 상태 이동과 삭제 같은 중요한 동작에는 취소·복구 가능한 피드백을 검토한다.
